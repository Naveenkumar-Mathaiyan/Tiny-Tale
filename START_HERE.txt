TINY TALE VERSION 7 - START HERE
===============================
This is an UPDATE for your existing Tiny Tale project.
It includes the website/admin changes and Android/iOS staff scanner SOURCE.
It does not contain an installable Android APK or iOS IPA.

STEP 1 - UPDATE YOUR ORIGINAL GIT FOLDER
1. Extract the ENTIRE ZIP to a short folder such as C:\TinyTale-v7.
2. Close your local Tiny Tale app windows.
3. Back up your original project folder and database before upgrading.
4. Double-click APPLY-UPDATE.bat in the extracted ZIP.
5. Enter the ORIGINAL folder you previously used for git push.
   Example: C:\Users\NaveenkumarMathaiya\Downloads\Tiny_Tale_Login_Fix_old
   The correct folder contains app.py and your existing Git repository.
6. The script copies code into that folder, retaining existing database,
   environment, uploaded files and Git history. Do not use the extracted
   release as a new Git repository. Existing product images are reused.

STEP 2 - PUSH THE UPDATED CODE
Open Command Prompt in your ORIGINAL Git folder and run:

git status

git add app.py operations.py enhancements.py management.py static/admin.html static/index.html static/admin.js static/admin-v5.js static/admin-v7.js static/store-v7.js static/operations.css mobile-scanner START_HERE.txt README.md UPDATE_GUIDE.md VERIFICATION.md tests

git diff --cached --stat

git commit -m "Add Tiny Tale scanner billing and storefront improvements"

git push origin main

Review the staged filenames before committing. Do not add API keys,
.env files, local databases, virtual environments or node_modules.
The mobile folder includes its own ignore rules for generated dependencies.

STEP 3 - DEPLOY YOUR TWO EXISTING RENDER SERVICES
1. Open your EXISTING tiny-tale-admin service on Render.
2. Select Manual Deploy > Deploy latest commit if auto-deploy did not run.
3. Do the same for your EXISTING tiny-tale-store service.
4. Both must keep their existing shared DATABASE_URL.
5. Keep the working Brevo settings on tiny-tale-store unchanged.
6. Do not create a new Blueprint or a replacement database for this update.
7. Open each service's /health URL. Version should be 7.0-stock-billing.
8. Hard refresh browser pages (Ctrl+F5), then sign in again.
   Older Store Keeper accounts become Store Manager and are signed out.

STEP 4 - SET UP YOUR ADMIN
- Homepage introduction: edit text/button, add 1-8 welcome images,
  remove old images, and choose auto-advance time (4-30 seconds).
- Offer banners: publish images/GIFs/videos; buttons/links remain optional.
- Product categories: add or rename categories. Store filters update too.
- Products & stock: upload multiple images/videos; choose an image thumbnail.
- Product photos & videos: search for the product; arrange its gallery.
- Staff accounts: create Store Manager, Manager, Supervisor or Billing staff.
- Codes & label printing: generate missing product-SIZE codes, customize
  codes if needed, select variants/copies, preview and print A4 at actual size.
  Internal Code 128 + QR works immediately. Licensed GS1 GTIN-13 is optional.
  Test one printed label before printing your full batch.
- Receive stock: scan/type a label, enter quantity, add to batch, then confirm.
- Counter billing: scan labels into a bill, record payment ALREADY collected,
  finalize once, and print/download the receipt. Stock deducts at finalization.
- Reports: choose counter sales or scanned movements, inclusive IST dates,
  then Generate. Preview PDF and download PDF/Excel.

IMPORTANT BILLING DETAILS
Counter billing records in-person payments; it does not collect money through
an online gateway and does not create a GST tax invoice. Website payments
remain simulated and website checkout has no Cash on Delivery.
Scanned stock movements and counter receipts share the existing database.
Stock changes appear in the website's existing refresh cycle (up to 20 sec).
If a save response is lost, RETRY THE SAVED BATCH. Do not enter it as a new sale.

STEP 5 - ANDROID / IPHONE STAFF APP
The source is in mobile-scanner. Read mobile-scanner\README.md.
Create a staff account in your web admin BEFORE trying the app.
Use the ADMIN URL (https://tiny-tale-admin.onrender.com), not the store URL.
An Expo/EAS build and signing setup is needed to produce installable apps.
Android preview builds produce an APK. iPhone installation needs Apple
signing/provisioning and registered test devices or TestFlight distribution.
No mobile signing credentials or app-store accounts are included in this ZIP.
