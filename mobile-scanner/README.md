# Tiny Tale Staff — Android / iOS source

This is an Expo SDK 57 React Native app using Expo Router, Camera, SecureStore and platform printing. It connects to your existing **admin** Render service. It is a staff scanner and counter-billing app, not a customer shopping app.

## Before using it

1. Deploy Tiny Tale v7 to both existing Render services.
2. Sign in to web admin as owner and create a staff username/password in Staff accounts. Use Store Manager for incoming stock only; Manager/Supervisor for incoming and sales; Billing staff for sales only.
3. Generate product-size labels in Codes & label printing. Print one and verify it before bulk printing.
4. On the app sign-in screen, keep `https://tiny-tale-admin.onrender.com` as the service URL. Use your assigned staff username/password. The owner’s blank-username login is intentionally web-only.

## Windows setup and development build

Install a current Node.js LTS version compatible with Expo SDK 57. Open Command Prompt in this `mobile-scanner` directory:

```bat
npm ci
npm run typecheck
npm run lint
npx eas-cli@latest login
npx eas-cli@latest build:configure
```

EAS prompts you to create/link an Expo project under YOUR account. Review the application identifier before the first released build; change `com.tinytale.staff` to an identifier controlled by your business if it is unavailable. Keep your EAS/Apple credentials out of Git.

Create an Android development build:

```bat
npx eas-cli@latest build --platform android --profile development
npx expo start --dev-client
```

Install the resulting development build on your Android phone and open the project from the dev client. For an installable preview APK that does not require the development server:

```bat
npx eas-cli@latest build --platform android --profile preview
```

Download the APK from your EAS build result and install it on a test Android device. No APK is included in this delivery.

For an iPhone preview:

```bat
npx eas-cli@latest device:create
npx eas-cli@latest build --platform ios --profile preview
```

This requires Apple Developer signing/provisioning. Register the test iPhone before building; ad-hoc builds install only on devices included in their provisioning profile. A production iOS build can later be distributed through TestFlight/App Store after your account and application setup. No IPA, Apple account or signing certificate is included. See [Expo internal distribution](https://docs.expo.dev/build/internal-distribution/) for account/device details. No build or publishing request has been submitted on your behalf.

## Using the scanner

- **Stock:** search product/category/size; refresh or leave this screen open for updates every 20 seconds.
- **Receive:** allow camera access, scan Code 128/QR/EAN-13, check product/size, enter quantity, add to batch, then confirm arrival.
- **Sales:** scan each variant, check quantities, choose payment already collected at the counter, and finalize. Website Cash on Delivery is unrelated and remains disabled.
- **Receipts:** review authorized receipts and use Print / save receipt. Platform print/save options depend on the device and installed printer services.
- Each camera scan stops the preview after one read; explicitly scan again to add another item. Repeated camera frames do not silently subtract stock.
- A pending batch is saved before submission. On connection failure or app restart, sign in with the SAME account and retry the saved batch. Its original request ID prevents a second deduction. Do not recreate an uncertain sale with a new ID.
- If your role changes or account is disabled, sign in again; disabled accounts are blocked. Tokens expire after 12 hours. Passwords are not saved by the app.
- If Render is asleep, open the admin website and wait for it to wake, then retry. All operations require a network connection.

## Verification and boundaries

TypeScript and lint passed. Android and iOS production JavaScript/Hermes bundles exported locally. This verifies source and module resolution, not native signing, native compilation or device functionality. Physical camera scan, printing, installation, session restoration across native restarts and live Render connectivity still require device acceptance tests.

The app has no real payment gateway or GST tax-invoice engine and does not support offline sales. Receipt totals use server prices and reject a changed amount before committing stock. Incoming and counter movements share the website database, but site stock can take its normal 20-second refresh interval to update visually.

The project’s package-lock.json pins the tested dependencies. Do not copy node_modules into Git or deploy it to Render. Android/iOS native folders are generated by Expo; configure them through app.json and EAS.
